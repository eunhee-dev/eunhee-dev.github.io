🎭 Part-aware Composition

프로젝트 기간: 2025. 12 - 2026. 01

복합 모션 프롬프트를 상체·하체·파츠 단위로 분해해 검색, 합성, 보정하는 파이프라인을 탐색했습니다. - `RQ1~RQ3`를 세우고, LLM 의미 분해가 실제로 part-aware generation의 입력이 될 수 있는지 검증했습니다. - `MoRAG-diffuse`, `ParCo`, rule-based concat + diffusion refinement를 병렬로 비교해 어떤 방식이 실제로 쓸 만한지 확인했습니다. - retrieval 품질이 낮으면 이후 단계가 모두 무너지고, refinement는 자연스러움은 높이지만 exact positioning에는 한계가 있다는 점을 정리했습니다. - 하나의 giant model 문제를 decomposition + retrieval + refinement 조합 문제로 재정의한 프로젝트입니다.

📍 풀어야 했던 문제

- As-is : 복합 프롬프트를 하나의 생성 모델에 바로 넣으면 상체/하체/세부 gesture 중 일부만 살아남기 쉬움 - 방향 전환, 세부 gesture, body-part constraint가 함께 있는 프롬프트에서 제어력이 급격히 떨어짐 - 검색 기반 접근은 조합 유연성이 낮고, 단순 concat은 경계가 부자연스러움 - To-be : part-aware decomposition + retrieval + composition 파이프라인 - LLM이 파트별 의미를 안정적으로 분리할 수 있어야 함 - 파트별 검색 결과를 조합한 뒤 refinement로 자연스러움을 회복해야 함 - exact positioning이 필요한 케이스와 아닌 케이스를 구분해 한계를 설명할 수 있어야 함

📍 업무 수행 내용

- 테스트용 프롬프트 리스트를 만들고 LLM 의미 분해 태스크를 먼저 검증 - `RQ1`: LLM이 파츠별 의미를 잘 분리하는가 - `RQ2`: 분리된 파트 정보로 적절한 motion retrieval이 가능한가 - `RQ3`: 임의 합성한 결과를 refinement로 자연스럽게 만들 수 있는가 - `MoRAG-diffuse` 기반 retrieval + composition, `ParCo` 기반 대안, rule-based concat + diffusion refinement를 병렬 실험 - prompt 수정 후 검색 -> 합성 품질 변화를 비교하고, retrieval이 실제 병목인지 refinement가 실제 병목인지 분리해서 확인 - refinement 테스트를 통해 자연스러움 향상 범위와 exact pose / position fidelity 한계를 문서화

📍 기여한 점

- 복합 프롬프트 문제를 하나의 end-to-end 생성기 문제가 아니라 조합 가능한 파이프라인 문제로 재구성 - 품질 이슈가 LLM decomposition, retrieval, refinement 중 어디서 발생하는지 구분 가능 - 제품화 시 디버깅 포인트와 개선 우선순위를 더 명확히 만들 수 있음 - part-aware decomposition과 retrieval-based composition이 실제로 의미 있는 접근임을 검증 - 후속 T2M retrieval/refine 프로젝트로 이어지는 직접적인 아이디어 자산 확보 - 실패 사례까지 포함해 어떤 경우 refinement만으로 해결되지 않는지 설명 가능 - 새로운 giant model을 바로 만들기보다 기존 자산을 조합하는 실용적 경로를 제안 - 모션 자산 재사용성과 실험 속도를 동시에 높일 수 있는 방향 제시 - 탐색 결과를 후속 파이프라인 설계의 근거로 남김
