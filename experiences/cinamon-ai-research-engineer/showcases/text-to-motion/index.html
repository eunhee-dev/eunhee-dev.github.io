🔠 Text-to-Motion

프로젝트 기간: 2025. 12 - 2026. 03

텍스트 조건으로 원하는 길이의 ==3D 캐릭터 모션==을 생성하는 ==diffusion 기반 text-to-motion 시스템==을 설계하고 배포했습니다. 데이터 파이프라인 점검, 모델 학습, 추론 최적화, API 서빙까지 전 과정을 담당했으며, classifier-free guidance와 DDIM sampling, Triton 기반 최적화로 기존 대비 ==10배 빠른 추론 속도==를 달성했습니다. 데모 페이지와 FBX viewer를 연동해 결과를 즉시 검증할 수 있는 사용 환경까지 구축했습니다.

📍 풀어야 했던 문제

- As-is : 유사도 기반 검색 모델은 품질이 안정적이고 가벼운 구조로 빠르게 서비스할 수 있었지만, 표현 범위가 확보한 데이터셋에 제한되고 원하는 길이로 생성할 수 없었습니다. - 폴리싱이 끝난 모션 캡처 원본을 그대로 활용할 수 있어 결과 품질은 우수함 - 어노테이션된 구간만 제공할 수 있어 길이 제어와 표현 확장에 한계가 있음 - To-be : 텍스트 조건을 반영하면서도 ==원하는 길이로 생성== 가능한 모델이 필요했습니다. - 검색 기반 방식보다 넓은 표현 범위를 제공해야 하고, 생성 기반 모델의 motion-text align을 향상시켜야 함 - 샘플링과 모델 최적화를 통해 ==서비스 가능한 추론 속도==를 확보해야 함

- Transformer Encoder 기반 denoising network를 적용해 가변 길이 생성에 유연하게 대응했습니다. - DDPM 1000 step sampling을 사용할 경우 300 frame 생성에 1분 이상 소요되어, ==DDIM 10 step==으로 줄여 샘플링 효율을 높였습니다. (FBX I/O 제외) - 생성 결과물의 아티팩트를 줄이기 위해 ==motion refinement 모델==을 후처리 단계에 적용했습니다. - 정합성이 검증된 모션-텍스트 데이터 쌍을 증강했습니다. (모션 데이터 2배, 텍스트 어노테이션 데이터 30% 증가) - 어노테이터가 작성한 데이터에 좌우 반전 기반 증강을 적용해 데이터 수량을 늘렸습니다. - left/right, clockwise/anticlockwise처럼 방향성이 포함된 어노테이션은 대응되는 반대 표현으로 함께 수정해 증강 데이터의 정합성을 유지했습니다. - ==Triton과 FastAPI==를 결합한 서빙 구조를 채택해 추론 최적화와 서비스 I/O를 분리했습니다. - FastAPI는 서비스에 필요한 데이터 I/O와 변환 로직을 담당합니다. - Triton은 최적화된 추론 로직을 담당합니다. - Dynamic batching을 적용해 ==GPU 자원 활용을 최적화==했습니다. - Ensemble model을 적용해 단일 Triton 서버 호출로 전체 추론 파이프라인을 실행할 수 있도록 구성했습니다.

📍 기여한 점

- 검색 기반 모델 대비 더 넓은 표현 범위와 ==길이 제어==가 가능한 모션 생성 기능을 구현했습니다. - 좌우, 시계/반시계처럼 방향성이 포함된 텍스트와의 정합성을 높였습니다. - 사용자가 원하는 길이로 모션을 생성할 수 있는 경로를 확보했습니다. - 데이터, 모델 학습, 최적화, 배포까지 전체 파이프라인을 연결했습니다. - ==ML lifecycle 전반==을 직접 운영하고 문서화해 팀 내 공유 자산으로 정리했습니다. - 병목 구간을 작은 단위로 나누어 진단하고 개선했습니다. - 엔지니어링, 클라이언트 등 타 팀과 협업하며 문제를 해결했습니다.
