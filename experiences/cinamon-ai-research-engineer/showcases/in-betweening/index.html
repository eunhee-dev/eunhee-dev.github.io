🎥 In-betweening

프로젝트 기간: 2025. 06 - 2025. 11

임의의 시작/종료 포즈 사이를 자연스럽게 연결하는 motion in-betweening 모델을 고도화했습니다. - Baseline P2P의 failure taxonomy를 먼저 정리해 short move, very long move, similar endpoint에서 왜 drifting / sliding / 멈춤이 발생하는지 분해했습니다. - P2P support model로 MDN 기반 프레임 수 예측기를 개발해 best test `MAE 37`을 확보했고, 비현실적인 길이 조건 입력을 줄였습니다. - DNO 기반 motion in-betweening을 비교해 장거리 연결 자연스러움과 dragging / sliding 감소 효과를 확인했습니다. - 동시에 optimize step `400`, sample generation `33~35초` 수준의 latency trade-off까지 정리해 서비스 적용 범위를 판단했습니다.

기존 시작/종료 구간 사이를 자연스럽게 메우는 transition 결과를 확인할 수 있습니다.

📍 풀어야 했던 문제

- As-is : baseline Pose2Pose는 짧은 거리, 매우 긴 길이, intro/outro가 유사한 경우에 drifting, sliding, 멈춤이 자주 발생 - 사용자가 길이를 직접 넣으면 비현실적인 duration 때문에 결과가 더 악화될 수 있음 - 단순 성능 비교만으로는 언제 어떤 모델을 써야 하는지 설명하기 어려움 - To-be : 자연스러운 transition을 생성하는 explainable한 P2P 경로 확보 - 입력 pose pair에 맞는 frame length를 자동 예측해야 함 - 장거리 이동과 다양한 transition에서 더 자연스러운 후보를 만들 수 있어야 함 - 품질뿐 아니라 latency까지 포함해 실제 서비스 적용 범위를 설명할 수 있어야 함

📍 업무 수행 내용

- baseline P2P failure taxonomy 정리 - 거리, 길이, endpoint 유사도, 속도 변화에 따라 실패 케이스를 분류 - short move / long move / similar endpoint에서의 거동 차이를 비교 - P2P support model 개발 - DETR과 MDN 계열을 비교하고, Gaussian mixture 기반 길이 예측기를 채택 - sigma clamp, entropy, reconstruction loss를 조정해 best test `MAE 37` 확보 - DNO motion in-betweening 기반 품질 개선 - base diffusion 재학습, DDIM inversion, velocity constraint, short-distance data oversampling 실험 - foot sliding, generation time, sampling step을 함께 점검해 trade-off를 정리 - P2P ONNX 구조, CI config, support model 통합 경로를 정리해 운영 가능한 형태로 다듬음

📍 기여한 점

- P2P를 무조건 교체하는 접근이 아니라 baseline과 DNO 각각의 사용 구간을 설명 가능한 상태로 정리 - 장거리 연결 자연스러움과 다양성은 DNO가 강하고, 실시간성과 짧은 거리 제어에는 한계가 있다는 점을 명확히 함 - 이후 API 통합과 제품 판단의 근거 자료로 활용 가능 - 길이 예측 지원 모델을 통해 사용자 입력 부담과 비현실적인 조건 입력을 줄임 - 생성 모델을 바꾸지 않고도 결과 안정성을 개선할 수 있는 축을 확보 - support model과 배포 구조를 함께 다루는 운영 경험 축적 - 품질, latency, 운영 구조를 한 화면에서 함께 설명할 수 있는 showcase 자산 정리 - 단순 데모가 아니라 실제 사용 조건을 설명하는 사례로 전환 - 후속 runner / 서빙 리팩토링의 기반을 마련
