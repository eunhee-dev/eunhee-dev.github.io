🎥 In-betweening

프로젝트 기간: 2025. 06 - 2025. 11

임의의 시작 포즈와 종료 포즈 사이를 자연스럽게 연결하는 ==motion in-betweening 모델==을 고도화했습니다. baseline의 failure case를 체계적으로 재현하고 분류한 뒤, ==diffusion noise optimization(DNO)==을 적용해 짧은 거리와 유사 endpoint 조건에서 발생하던 ==drifting 문제==를 완화했습니다. 모델 서빙과 데모 페이지까지 연결해 결과를 바로 검증할 수 있는 형태로 배포했습니다.

기존 시작/종료 구간 사이를 자연스럽게 메우는 motion in-betweening 결과를 확인할 수 있습니다.

📍 풀어야 했던 문제

- As-is : baseline 모델은 짧은 거리 이동이나 intro/outro가 유사한 경우 아티팩트를 만들었습니다. - 짧은 거리에서는 drifting 후 이동하는 부자연스러운 전환 모션이 생성됨 - 모션의 역동성에 비해 연결 시간이 길면 부자연스러운 전환 결과가 생성됨 - To-be : 더 자연스러운 전환 모션을 생성하는 motion in-betweening 모델이 필요했습니다. - 짧은 거리 이동이나 긴 연결 시간에서도 ==자연스러운 전환 모션==을 생성해야 함 - 임의의 intro/outro 모션에도 ==안정적으로 대응==해야 함 - 기존 baseline 수준의 latency를 최대한 유지하면서도 품질을 개선할 수 있어야 함

📍 업무 수행 내용

- baseline의 failure case를 확보하고 분석 리포트를 작성해 개선 우선순위를 정리했습니다. - 거리, 길이, endpoint 유사도, 속도 변화를 기준으로 실패 케이스를 분류했습니다. - short move, long move, similar endpoint 조건에서 전환 모션의 차이를 비교했습니다. - 작성한 리포트를 바탕으로 고도화 모델에서 개선이 필요한 문제를 구체적으로 정의했습니다. - diffusion noise optimization 기반 접근으로 품질을 개선했습니다. - ==pretrained diffusion prior==를 활용해 샘플링 시 ==최적화 기법==을 적용했습니다. - intro/outro motion을 제약으로 두고, 나머지 시퀀스는 랜덤 노이즈에서 시작하도록 구성했습니다. - 지정한 횟수만큼 denoising을 반복하며 원본 intro/outro 정보와의 MSE loss를 줄이는 방향으로 초기 노이즈를 업데이트했습니다. - 다양한 이동 시나리오에서도 더 자연스러운 전환 모션을 생성했습니다. (Media 3) - ==TorchServe== 기반 모델 서빙과 데모 페이지, 쇼케이스를 제작했습니다. - 인퍼런스 시 성능과 속도 간 trade-off를 고려해 optimize step 400을 적용했고, 샘플 1개당 약 30초가 소요됐습니다. - 이후 후속 프로젝트에는 ==Triton과 FastAPI== 기반 서빙 로직을 적용했습니다.

📍 기여한 점

- 최적화 기반 motion in-betweening 샘플링 로직을 적용해 기존 baseline의 ==failure case를 완화==했습니다. - pretrained diffusion model의 prior knowledge를 활용해 유지보수 비용을 낮췄습니다. - baseline과 비교 가능한 성능 리포트를 작성해 ==의사결정을 위한 근거 자료==를 제공했습니다. - failure case 개선 결과를 쇼케이스로 정리하고, API 호출 기반 모델 추론 데모까지 제공했습니다.
